# 新蓝恒成公司网站 — 完整技术方案与开发计划

> 基于 `xinlan_web.md` 开发文档、`pnp/` 品牌资源文件夹、`final_mockup_website.png` 参考设计稿编制。
> 技术栈决策：**前端 Next.js + 后端 Express 自研全栈**（用户已确认）。

---

## 一、方案概述

为湖南新蓝恒成信息技术有限公司构建一套企业官方网站，包含 7 个前台页面 + 后台内容管理系统（CMS）。前台具备营销展示能力（响应式、SEO 友好、性能达标 LCP≤2.5s），后台支持 RBAC 权限下的新闻/产品/方案/招聘/留言/页面配置全功能管理。

- **公司品牌**：XINLAN HENGCHENG / 新蓝恒成
- **品牌口号**：外稳内动，恒久达成
- **主色调**：科技蓝 `#1a56db` / `#2563eb` + 深色系
- **字体**：中文思源黑体/微软雅黑，英文 Inter/Helvetica
- **响应式断点**：Desktop ≥1200px、Tablet 768–1199px、Mobile <768px

## 三、技术架构设计

### 3.1 技术栈选型
| 层级 | 选型 | 理由 |
| :--- | :--- | :--- |
| **前端框架** | Next.js 14 (App Router) | SSR/SSG 支持，SEO 与 LCP 性能最优；复用 React 技能 |
| **前端语言** | TypeScript | 类型安全，降低维护成本 |
| **样式方案** | Tailwind CSS + CSS Modules | Tailwind 提速响应式开发，CSS Modules 处理组件级隔离 |
| **UI 组件库** | 自建组件 + Radix UI 基元（无样式） | 保证设计还原度，避免组件库样式冲突 |
| **动画** | Framer Motion | 声明式动画，Hero/滚动揭示交互 |
| **图标** | lucide-react + 自定义 SVG | 轻量，契合科技蓝风格 |
| **后端框架** | Node.js + Express | 匹配用户技能栈，自研全栈灵活可控 |
| **ORM** | Prisma | 类型安全，迁移管理，对接 MySQL |
| **数据库** | MySQL 8.0 | 文档表结构为关系型，MySQL 稳定成熟 |
| **认证** | JWT (jsonwebtoken) + bcrypt | 文档要求 bcrypt/Argon2 + RBAC |
| **校验** | Zod | 前后端共享 schema，统一校验 |
| **限流** | express-rate-limit | 防暴力破解/DDoS |
| **日志** | Winston + Morgan | 访问日志 + 操作审计日志 |
| **部署** | 前端 Vercel / 后端 Docker + 云服务器 | 前端 CDN 加速，后端容器化部署 |
| **图片优化** | Next.js `<Image>` + WebP | 自动响应式图片，降低 LCP |

| 页面 | 路由 | 渲染策略 | 数据来源 |

| 产品与服务 | `/products` | SSG + ISR | `products` 列表 |

| 后台管理 | `/admin/*` | CSR（鉴权） | 全部表 CRUD |

### 3.4 响应式布局方案
- **断点**（与文档一致）：`sm:768px` / `lg:1200px`
- **栅格**：Tailwind 12 列，Desktop 多列布局、Tablet 两列/单列、Mobile 单列堆叠
- **导航栏**：Desktop 横向菜单 + CTA 按钮；Mobile 汉堡菜单 + 抽屉式导航
- **Hero**：Desktop 全屏背景图 + 文案左对齐；Mobile 背景图 + 文案居中堆叠
- **价值卡片**：Desktop 4 列、Tablet 2 列、Mobile 1 列
- **图片**：统一使用 `next/image`，自动生成 srcset，避免移动端加载桌面大图

### 3.5 性能优化策略
| 策略 | 实现 |
| :--- | :--- |
| **首屏加速** | 首页 SSG 预渲染 + ISR；Hero 图优先级 `priority` |
| **图片优化** | WebP/AVIF 自动转换 + 响应式尺寸 + 懒加载 |
| **代码分割** | 动态导入非首屏组件（如 Framer Motion 重动画） |
| **字体优化** | `next/font` 自托管 Inter + 思源黑体子集，消除 FOUT |
| **缓存** | API 响应 Cache-Control；静态资源 CDN 长缓存 + hash 命名 |
| **Bundle 控制** | Tree-shaking；避免整包引入大库 |
| **目标** | LCP ≤ 2.5s、FID ≤ 100ms、CLS < 0.1 |

### 3.6 兼容性处理
- 目标浏览器：Chrome / Firefox / Safari / Edge 最近两个稳定版本
- PostCSS + Autoprefixer 自动加前缀
- 使用 `@supports` 对 CSS 新特性做降级
- `<picture>` 标签对 AVIF/WebP 降级到 JPEG
- 移动端 iOS Safari 适配（100vh 问题用 `dvh` 处理）

## 四、数据库与 API 设计（沿用文档规格）

### 4.1 数据库表（7 张，详见 `xinlan_web.md` 4.2 节）
- `users`（id, username, password, role[admin/editor], timestamps）
- `news`（id, title, slug, summary, content, cover_image, category, tags, status[draft/published], view_count, published_at, timestamps）
- `products`（id, name, slug, category, description, features[JSON], cover_image, images[JSON], sort_order, status[active/inactive], timestamps）
- `solutions`（id, title, slug, industry, content, cover_image, sort_order, status, timestamps）
- `jobs`（id, title, department, location, type[full-time/part-time/intern], description, requirements, status[open/closed], timestamps）
- `messages`（id, name, phone, email, company, content, status[pending/read/replied], timestamps）
- `page_configs`（id, page, section, content[JSON], updated_at）

**实施要点**：用 Prisma `schema.prisma` 建模，`npx prisma migrate dev` 生成迁移；slug 字段加唯一索引；status/role 枚举用 Prisma enum；JSON 字段（features/images/content）用 `Json` 类型。

### 4.2 API 端点（11 个，详见 `xinlan_web.md` 4.3 节）
| 接口 | 方法 | 鉴权 | 说明 |
| :--- | :--- | :--- | :--- |
| `/api/news` | GET | 公开 | 列表（分页/分类/标签） |
| `/api/news/:slug` | GET | 公开 | 详情 |
| `/api/products` | GET | 公开 | 列表 |
| `/api/products/:slug` | GET | 公开 | 详情 |
| `/api/solutions` | GET | 公开 | 列表 |
| `/api/solutions/:slug` | GET | 公开 | 详情 |
| `/api/jobs` | GET | 公开 | 列表 |
| `/api/jobs/:id` | GET | 公开 | 详情 |
| `/api/messages` | POST | 公开（限流） | 提交留言 |
| `/api/contact` | POST | 公开（限流） | 合作咨询 |
| `/api/admin/*` | * | JWT + RBAC | 后台 CRUD |

**实施要点**：Zod 定义请求 schema 共享前后端；列表接口统一分页参数 `?page=&pageSize=&category=&tag=`；错误响应统一格式 `{ code, message, details }`。

## 六、开发步骤规划（按优先级）

### 阶段 1：基础项目搭建（环境与骨架）
1. 初始化 `frontend/`（Next.js + TS + Tailwind）与 `backend/`（Express + Prisma）
2. 配置 ESLint / Prettier / TypeScript 严格模式
3. 编写 `prisma/schema.prisma`（7 张表），生成迁移并 seed 测试数据
4. 搭建 Express 中间件骨架（cors/helmet/json/morgan/error）
5. 配置环境变量（`.env`：DATABASE_URL、JWT_SECRET、API_BASE）
6. 设计全局样式 token（颜色 #1a56db/#2563eb、字体、间距）
7. 将 `pnp/` 资源分类导入 `frontend/public/`
8. **产出**：可运行的空项目骨架 + 数据库就绪 + 设计 token

### 阶段 2：页面布局与组件拆分
1. 实现 `layout.tsx` 根布局（Navbar + Footer + 字体加载）
2. 开发 `Navbar`（桌面横向 / 移动抽屉）+ `Footer`
3. 拆分首页区块组件：`Hero` / `ValueCards` / `AboutEntry` / `ProductPreview` / `NewsPreview`
4. 实现 `shared` 组件：`Button` / `Card` / `Section` / `Breadcrumb` / `Pagination`
5. 搭建 7 个前台页面空壳（静态文案），完成路由跳转
6. 实现响应式断点适配（Tailwind sm/lg）
7. **产出**：全部页面静态版本，响应式可浏览

### 阶段 3：核心功能模块（按优先级）
**P0 — 后端 API（支撑前台）**
1. 公开 GET 接口：news/products/solutions/jobs 列表 + 详情（分页/筛选）
2. POST 接口：messages / contact（Zod 校验 + 限流）
3. 后台鉴权：登录（JWT 签发）+ auth 中间件 + RBAC

**P1 — 后台 CMS**
4. 后台布局：登录页 + Dashboard + 侧边栏导航
5. 各模块 CRUD：news / products / solutions / jobs（列表/新增/编辑/删除/状态切换）
6. 留言管理：列表 + 状态流转（pending→read→replied）
7. page_configs 编辑器：首页各区块内容配置
8. 用户管理：账号增删 + 角色分配

**P2 — 前台数据对接**
9. 前端 API 客户端（`lib/api.ts`，封装 fetch + 类型）
10. 首页数据对接（page_configs + 最新产品/新闻）
11. 列表页对接（分页/筛选交互）
12. 详情页对接（SSG/ISR getStaticProps + fallback）
13. 联系页表单对接（提交 + 成功/失败反馈）
14. **产出**：全栈功能闭环，前台后台均可使用

### 阶段 4：交互效果与动画
1. Hero 滚动视差 + 文字淡入（Framer Motion）
2. 价值卡片悬停浮起 + 滚动揭示
3. 导航栏滚动透明度过渡
4. 页面切换过渡动画
5. 按钮/链接微交互（hover/active）
6. 后台表格/表单交互优化（loading/skeleton/toast）
7. **产出**：符合设计稿的动效体验

### 阶段 5：内容填充与优化
1. 录入真实公司内容（简介、产品、方案、职位、联系方式）
2. SEO 优化：每页 `metadata`（title/description/og）、sitemap.xml、robots.txt
3. 图片优化：WebP 转换 + alt 文案 + 尺寸压缩
4. 可访问性：语义化标签、aria 属性、键盘导航、对比度
5. **产出**：内容完整、SEO 就绪的成品

### 阶段 6：测试与调试
1. 单元测试：后端 service/controller（Jest）、前端组件（Vitest + Testing Library）
2. E2E 测试：关键流程（Playwright）：首页浏览、新闻筛选、留言提交、后台登录+CRUD
3. 兼容性测试：Chrome/Firefox/Safari/Edge + PC/平板/手机
4. 性能测试：Lighthouse 跑分（LCP≤2.5s、FID≤100ms、CLS<0.1）
5. 安全测试：输入校验、SQL 注入、XSS、越权访问扫描
6. Bug 修复与回归
7. **产出**：通过验收标准的可上线版本

| 内容管理 | 后台可 CRUD 所有内容 | 阶段 3 P1 后台 CMS |
| SEO | Meta 标签可自定义 | page_configs + metadata API |

### 7.3 问题反馈与调整机制
- **每日同步**：站会同步进度与阻塞
- **每周评审**：周五演示当周产出，对照里程碑验收
- **变更流程**：需求变更需书面记录，评估影响后排期
- **缺陷管理**：Bug 用 issue 跟踪，按 P0/P1/P2 分级，P0 当日修复
- **验收节点**：每个里程碑需客户签字确认后进入下一阶段
